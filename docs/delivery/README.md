# Delivery records

Create dated plans and verification records here for substantial features, migrations, and releases. This directory contains no inherited evidence that claims a newly generated product is tested.

Examples of names: `2026-09-12-feat-001-plan.md`, `2026-09-12-v0.1.0-verification.md`. Use the [plan](../templates/implementation-plan.md) and [verification](../templates/verification.md) templates when useful. Keep historical reports fixed except for explicit corrections. Put current behavior in specifications and current work in the status file.
