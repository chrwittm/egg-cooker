**Updated:** 2026-09-16

**Backlog:** [FEAT-001](../../planning/backlog.md)

## User outcome and motivation

Set the egg and preferred doneness, start when it is in the heat, and watch an engaging cross-section cook alongside the countdown. Nail the science inputs, look and feel, and animation before adding modes.

**Two screens: Configure → Cook.** Completion, recovery and cancellation are states or small overlays within those screens. Preparation, cooling and finishing as a guided process belong to [FEAT-002](0002-guided-cooking.md), not this MVP.

**Design rule:** remove unnecessary parts, controls and words. Show the egg, values, choices and one primary action. Use short labels/icons; keep explanations in contextual details. Minimal visible copy does not remove accessible names, failure feedback, attribution or an informed location choice. No permanent instructional paragraphs, setup checklist or educational dashboard.

## Scope and non-goals

Required: chicken-egg mass slider with S/M/L/XL presets, starting-temperature slider with fridge/room presets, continuous texture with three preset anchors, automatic local conditions on request, estimated time, animated egg, absolute-time timer, cancellation/back, simple sound, a clearly marked fast-forward demo, reduced motion and same-tab real-cook recovery.

GitHub Pages remains the only deployment target. Calculations, state and animation stay in browser TypeScript/Svelte/CSS. Maintainer review **adds browser-called elevation/weather APIs and an optional locality API** to the MVP: elevation and weather pressure. Elevation/weather integration is required; user permission and successful networking are not required to start a baseline cook. No backend, proxy, secrets, accounts, cloud sync, server notifications, alternate hosting or paid-service workaround. Bundle all cooking logic/assets; the loaded journey keeps working without network.

No quantity control, method selector or method-specific offset. The model approximates an individual egg in a sustained boiling environment, either submerged water or saturated steam in an ordinary covered, unpressurized pot. Sharing that approximation does not establish identical outcomes; [method validation](0001-mvp-science.md) is required. No cold-start, pressure-cooker, sous-vide or microwave mode.

Deferred: Guided cooking; calibration/feedback; history; multiple species and multi-egg scheduling; Egg Lab/camera; smart-home integration; sound personalities; PWA/offline opening; wake lock; haptics; language/theme switching. See the promoted items in the [real backlog](../../planning/backlog.md). The MVP includes a small demo control, not a general developer/admin panel.

### Environmental lookup contract

Use the browser Geolocation API for coordinates, then **Open-Meteo Elevation API**, then **Open-Meteo Forecast API current surface pressure**. An independent optional BigDataCloud request supplies the city/locality label. GPS is not guaranteed: browser location may use other sources. The science record links provider documentation and research evidence.

1. One tap immediately starts lookup and remembers the boolean automatic-location preference. The browser owns its permission prompt and retention. No app “Are you sure?” overlay. On a visible new visit, refresh once only when the preference is on, no cook is active and the Permissions API reports `granted`; prompt/denied/unsupported waits for a tap. No automatic prompt or polling.
2. Call `getCurrentPosition` with `enableHighAccuracy: false`, `timeout: 10000`, `maximumAge: 600000`. Validate finite latitude −90…90, longitude −180…180 and nonnegative accuracy; accuracy above 1000 m means “Location imprecise” and fallback. Round coordinates to three decimals. Do not use browser altitude.
3. GET `https://api.open-meteo.com/v1/elevation?latitude={lat}&longitude={lon}`. Require a single numeric elevation **−500…8850 m**. Then GET `https://api.open-meteo.com/v1/forecast?latitude={lat}&longitude={lon}&elevation={height}&current=surface_pressure&timeformat=unixtime&timezone=GMT`.
4. Validate numeric current surface pressure **300…1100 hPa**, hPa and unixtime units, integer model timestamp, zero UTC offset and returned elevation within 1 m of the request. Accept timestamps from two hours ago to 15 minutes ahead of real device time. Use surface pressure once; never substitute `pressure_msl`. Convert to boiling temperature locally.
5. Keep the previously displayed conditions, estimate and place while the pipeline is pending. Apply its final conditions together. Delay progress by **800 ms**, prevent duplicate activation immediately without dimming. Cancel lookup keeps current values; a completed failure/timeout applies the established fallback. Pending altitude is internal, not a newly displayed estimate.
6. In parallel, optionally GET `https://api.bigdatacloud.net/data/reverse-geocode-client?latitude={lat}&longitude={lon}&localityLanguage=en`. Only use fresh browser-derived coordinates from the calling client; no IP fallback, server call or saved-coordinate lookup. Validate coordinate-derived source and returned coordinates within 0.001°, then a nonempty city or locality string ≤120 characters without control characters. Render escaped text. The name never changes conditions, duration or failure policy; a slow name can arrive after weather, guarded by the same cancellation generation. Failure leaves the source label usable without a name. A new completed lookup clears an old name if no replacement exists; manual edits clear it immediately. Never persist coordinates or place names.

Each fetch has an 8-second abort deadline, credentials omitted, no custom authorization/header or API key, JSON size capped at 64 KiB, HTTP-success and shape/type validation. Ignore harmless extra API fields for forward compatibility; reject arrays/missing required fields/error objects/wrong units. Do not render provider error text as HTML.

A tap/retry or the permitted one-time visit refresh starts lookup. One pipeline at a time; further activations while pending are ignored. No network polling, automatic retry or tracking. Keep accepted conditions in memory for this page. In Configure, check weather freshness on focus/visibility, once per minute and at Start. Expired weather falls back to the stored altitude estimate and updates the displayed duration. If Start itself discovers expiry, refresh the estimate with **Conditions updated**, without committing; the next Start activation uses that displayed estimate. Retry reacquires location. Actual raw coordinates and responses are discarded after completion/failure; there is no location history. API freshness uses real time, not the accelerated demo clock. An already committed cook never changes conditions on expiry.

| Outcome                                                                             | Conditions used / visible response                                                                                                                                                                        |
| ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Both APIs succeed                                                                   | Returned surface pressure; **[City] · [p] hPa**, or **Local · [p] hPa** without a city/locality; details show elevation, source and model time                                                            |
| Permission denied/unavailable, inaccurate location, elevation failure/outside range | Standard 1013.25 hPa; **Standard** and brief contextual failure with Retry. Do not silently call this local.                                                                                              |
| Elevation valid, weather timeout/offline/429/malformed/stale                        | Derive standard-atmosphere pressure from that elevation; **Altitude estimate**; details: weather unavailable, Retry                                                                                       |
| Refresh fails after previous success                                                | Select the fresh attempt's valid altitude estimate, or standard if elevation failed; never relabel stale weather as fresh.                                                                                |
| Start while lookup pending                                                          | Start immediately with the currently displayed accepted conditions. Abort outstanding fetches, invalidate the request generation and ignore later geolocation/fetch callbacks. No mid-cook duration jump. |
| Cancel lookup                                                                       | Abort/invalidate pipeline and retain displayed conditions.                                                                                                                                                |

Manual elevation/pressure changes cancel outstanding work and clear the locality label. The standard fallback is explicitly unadjusted for the user's actual location. Successful environmental integration is a release requirement; fallback is resilience, not permission to leave those APIs unimplemented.

### Two screens and transitions

Configuration is ordered: header → size → starting temperature → texture → environment → egg → Start. Cook is ordered: utilities → countdown/Ready → egg → demo speed → Stop timer when Ready → Cook another egg. About holds credits, model limits and data-sharing details; no permanent footer slogans.

| Event            | Result                                                                                                                                                                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Start            | Freeze validated inputs, pressure/source and model version; commit one absolute start time before effects. Start means the egg is already in boiling water or saturated steam. No preparation confirmation. Cancel all outstanding lookup/permission work. |
| Transition       | Configuration slides upward; the same egg moves/enlarges into Cook over 1000 ms with gentle easing. The timer starts immediately. Return reverses the journey. Reduced motion is immediate.                                                                |
| Cooking          | Stable countdown and continuous egg. Demo speed is on Cook. No editing or pause.                                                                                                                                                                           |
| Back             | Immediately silence, delete active storage and return to preserved configuration, both before and after Ready. No cancellation dialog. Screen-reader early-exit notice reminds that the egg remains in heat.                                               |
| Target           | Same screen: **Ready**, +m:ss, one completion announcement and persistent alarm. Demo resets to 1× exactly at target.                                                                                                                                      |
| After target     | Time continues, image advances toward Firm then clamps. No additional firmness is claimed.                                                                                                                                                                 |
| Stop timer       | At Ready, below speed and above Cook another egg. Freeze time and frame, silence sound, cancel rendering and delete active storage. Show **Egg taken out**; hide speed and Stop. This is an in-memory acknowledgement, not saved history or a pause.       |
| Cook another egg | Below the egg. End the timer and slide back to preserved configuration. Also available directly while overdue.                                                                                                                                             |

Duplicate Start cannot replace a session or duplicate alarms. Ignore repeated double-click continuation across navigation. Early removal uses Back; Guided cooling remains deferred in 0002.

### Timing, background and recovery

Use an injectable clock and plain TypeScript state transitions. At start, `startAtMs = clock.now()` once, `targetAtMs = startAtMs + durationSeconds*1000`. Validate positive safe integer timestamps before commit. Commit synchronously before audio/network/storage effects. Never delay time zero for animation/audio. Every refresh/action/resume uses the same `now` sample for timer, state and SVG geometry:

```text
elapsedMs = max(0, now - startAtMs)
remainingSeconds = ceil(max(0, targetAtMs - now)/1000)
alert = now >= targetAtMs
overdueSeconds = floor(max(0, now - targetAtMs)/1000)
```

At target−1 ms show 0:01; at target show Ready and +0:00; at target+1 s show +0:01. Use tabular `m:ss`, adding hours if necessary. Foreground updates reflect elapsed time within one second when browser execution is available. Callbacks and animation-frame counts never accumulate elapsed truth.

On hidden/pagehide stop rendering work and save best-effort; on visible/pageshow/focus derive current state before rendering. Same-tab reload with a valid record shows the current frame/time, with a compact **Recovered · Still cooking?** overlay; **Yes** dismisses it, **Done** finishes. Time continues beneath it, sound is off until re-enabled. A past target shows Ready/overdue immediately, not a restarted duration. No historical removal time is guessed.

Browser navigation is not trapped and steps do not create routes. Back/forward restoration re-reads storage before reviving memory. Session loss leads to Configure with defaults. Closed-tab/new-device recovery and offline reopening are not promised. A ≥24-hour saved cook shows **Old timer** with **Discard**, no alarm. Backward movement relative to the last in-memory time sample or saved timestamp, or invalid time, enters **Time uncertain** on Cook: freeze last trusted image, hide the countdown, silence and attempt to delete the record; **Cancel cooking** returns to Configure. Do not create a new target. Forward clock changes derive overdue normally; after reload they cannot be distinguished from real absence. Correct device time is assumed; timezone changes do not alter Unix timestamps.

Correct recovery when execution resumes is not a guaranteed alarm while the browser/device is suspended. Info and the bell's accessible help state: keep the page visible/device awake for best chance of hearing it. No wake-lock, notification or service-worker workaround. After the app has fully loaded, all cooking/animation/audio works offline. API loss selects the stated fallback before start; committed conditions never change. Reload/opening offline may fail, including when the browser discarded the page.

### Signature animation and motion

Render one original inline SVG using shell outline, clipped white layer and yolk with a glossy center and matte outer annulus. No rendering dependency, remote image, Canvas/WebGL or sensor-style display. Warm off-white background, dark type/outline, amber actions and yolk supply the visual identity. The white needs a contrasting underlay so becoming opaque is visible. Selections expose pressed state and use fill/outline emphasis without ticks.

Compute rounded Soft/Jammy/Firm times **S/J/F** for the selected mass, actual starting temperature and committed pressure. Regardless of chosen doneness, equal elapsed time and equal physical inputs produce the same image. Changing doneness changes the target/preview; changing pressure, mass or starting temperature changes the timeline. Timer and image must agree after every jump/recovery.

| .25S                  | .25                          | 0                           | Visible opaque white band beginning at shell                                     |

Fractions are **illustrative geometry**, not measured coagulated volume, temperature fields or validated protein kinetics. Linearly interpolate between anchors from absolute elapsed time, without an independent CSS timer. The science-informed timing is required; a validated thermal “digital twin” is not claimed. Info states “Illustrated progress, not a measurement inside the egg.” No internal temperature labels, heat-map legend or percent-cooked claim. Accessible stage names describe the illustration, not a verified egg condition.

Start and return move the shared egg with measured position/size over 1000 ms. Controls move out above it; Back enters separately. Input preview follows the current setting without a decorative preset animation. Time jumps render the correct frame immediately. One column stays at most 440 px wide even on desktop; short screens, landscape and enlarged text scroll naturally. No flashing, bouncing or looping celebration.

Reduced motion removes the upward movement, fades and interpolation; display the latest reached storyboard anchor with the correct countdown and accessible stage. Target previews remain distinct. Normal-mode visual acceptance requires watching an actual smoothly transforming egg, not only comparing end screenshots.

### Sound, demo and access

**Sound:** requested-on bell; Start creates/resumes Web Audio and plays a quiet activation cue. Failure shows **Sound unavailable** without delaying the clock. In the final ten countdown seconds, tick once per displayed second. Do not replay skipped seconds; keep at least 900 ms real-time spacing in accelerated demos. At target replace any tick with a clear ascending/descending three-tone alarm (880/1100/880 Hz, ~0.64 s). Repeat every **two real seconds** for as long as Ready remains active, visible and sound-enabled, until Stop timer, Back, Cook another egg or mute. No one-minute cutoff; no overlapping or catch-up burst. Hidden pages stop sound; visible return derives current state. Reload remains silent until enabled; already-overdue recovered sessions only preview when enabled. Actual-device audibility and suspension behavior remain Pending.

**Demo:** defaults on for testing, starts at **1×**; visible DEMO badge and Start demo. On Cook offer **1× / 10× / 20× / 50× / To end**. Changing speed preserves elapsed virtual time. Crossing the target resets to 1× at the exact target; later acceleration is allowed. Real timers cannot accelerate. Demo uses the same domain/time/illustration path but is never persisted. Preserve selected mode between eggs; fresh page without a real recovered cook defaults to demo. Audio cadence follows real time.

**Accessibility:** native labeled sliders with min/max/current value and `aria-valuetext` including category/grams or Celsius; arrows and Home/End fine-tune. Preset buttons expose selected state; doneness has preset buttons and a native slider. Icon-only controls have accessible names, visible focus and at least 44×44 px targets. Body text ≥4.5:1 contrast, large text ≥3:1, meaningful borders/focus ≥3:1. At 200% text zoom/320 px reflow everything remains reachable. Focus the new screen heading on user navigation; trap/restore dialog focus and support Escape. Announce start, recovery and cancellation politely and completion once assertively, never each second. Countdown remains manually readable with live updates off. Hide decorative SVG internals from screen readers and supply a concise text stage. At timed Alert focus the heading once, never repeatedly. Retain short necessary labels and error text even when the visual design is otherwise word-light.

## Data, privacy, security, compatibility

Persist only a real active cook in `sessionStorage`, key `egg-cooker.active-cook.v1`. Exact fields: `schemaVersion: 1` / `modelVersion: "williams-pressure-v1"` for named texture, or `schemaVersion: 2` / `modelVersion: "williams-pressure-v2"` for numeric texture, `massG`, `initialTemperatureC`, `doneness` (`soft|jammy|firm` or numeric 0.75–2.25 in 0.01 steps), `pressureHpa`, `source` (`standard|altitude|weather|manual`), `altitudeM`, `weatherTimeSeconds`, `startAtMs`, `targetAtMs`, `durationSeconds`, `savedAtMs`. Mass/temperature/duration are integers. Both nullable fields are always present: altitude is null for standard, weather time is null except for weather. No coordinates, city names, raw responses, sound preference, frame state, demo, completed history or Cooling phase. Separately persist only the automatic-location boolean in localStorage at `egg-cooker.auto-location.v1`; About removes it. Numeric-range expansion retains v2 because equations and existing valid snapshot results are unchanged.

Read once before enabling Start and re-read on pageshow restoration. Reject over-4096-character values before JSON parsing. Require a plain object with exact schema fields/enums/types, finite supported values, positive safe integer millisecond timestamps, `startAtMs <= savedAtMs`, exact target/duration identity and recalculated duration matching the recorded model. Standard records require 1013.25 hPa and null altitude/weather time; altitude records require valid height and its computed pressure; manual records require valid height/pressure and null weather time; weather records require valid height and integer model time within the freshness window relative to start. The committed weather timestamp may be old on recovery: preserve the original valid cook snapshot instead of recalculating with current weather. Unknown versions do not migrate automatically.

Write synchronously at Start and best-effort on hiding/pagehide (not every frame); remove on Stop timer/Cook another egg/Back/discard or Time uncertain. On corruption/version mismatch: **Cannot recover timer**, **Discard**; never guess a start time. Denied access/write failure keeps an in-memory cook with **Recovery unavailable** and contextual explanation. Attempt to remove stale data after a failed update; if removal also fails, explain that an older timer may reappear. Failed deletion never revives the current cook. Never clear other storage keys. A missing record opens defaults; same-tab storage is best-effort, not guaranteed durable or synchronized between duplicated tabs.

Application code sends rounded coordinates and IP-bearing HTTP requests to Open-Meteo and BigDataCloud only for an activated or remembered permitted lookup; do not describe that as “no uploads.” Provider logging/retention and attribution are documented in the science record. The free endpoints are selected for this personal non-commercial app; commercial use, changed terms or loss of browser access requires a fresh decision, not an embedded secret or proxy. No runtime package dependency is needed for fetch, geolocation, audio, SVG or arithmetic.

English UI, grams/Celsius and EU size labels. Proposed release targets: current stable Safari/iPhone, Chrome/Android and desktop Safari/Chrome/Firefox at release, with exact tested versions recorded. Embedded browsers and installed PWA mode are not certified. Browser WebKit tests are not proof of iPhone audio/background behavior. If HTML loads but scripts fail, show a small static retry message; if HTML cannot load, the browser owns the network error. All cooking code/assets must be ready before Start. All paths use the configured Vite base; no deep routes or server fallback.
