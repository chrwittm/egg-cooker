# FEAT-006 — Continuous controls and an easier finish

**Status:** Accepted from the maintainer's 2026-09-15 review. Refines [0003](0003-mobile-interaction.md) and [0001](0001-mvp.md). Implementation authorized; publication remained a separate decision.

## Outcome and replacements

A compact configuration with grouped preset rails: tap a familiar preset or drag its native slider within the same enclosure. This replaces separate outlined buttons and sliders, discrete-only texture, the Jammy default, the app's location confirmation and early-cancel dialog. Existing pressure, failure, recovery and demo contracts remain except as stated here.

- Fresh defaults: M / 60 g, Fridge / 8 °C, Soft. Preset buttons retain 44 px touch height; continuous tracks have at least 26 px input height, with separate non-overlapping targets, native keyboard semantics and visible focus. Environment tracks are 32 px. Phone fit must preserve reflow, not clip overflow on short screens or enlarged text.
- Continuous texture spans 0.75–2.25 times the unrounded Soft heating time, in 0.01 steps. Named anchors remain Soft 1, Jammy 1.5, Firm 2. This extends the provisional texture mapping rather than claiming a measured consistency scale. Very soft is explicitly exploratory; no food-safety guarantee. Round only the final duration. Target illustration follows the calculated duration on the existing continuous illustration timeline.
- Keep named preset values compatible with schema 1 / `williams-pressure-v1`. Numeric texture snapshots use schema 2 / `williams-pressure-v2`, with the same exact field set and storage key. Strict recovery accepts both known versions, checks type/version agreement and recalculates duration; unknown/mismatched versions are invalid. No saved cook is silently rounded to a preset.
- Group elevation and pressure in one inset surface with an integrated location/refresh action. Keep source feedback there; move provider links into About. Increase preview egg from 124 to 142 px base width on tall screens, preserving cube-root mass scaling; reduce the base to 80 px at heights up to 740 px. Target one-screen configuration at 390 × 844 and 390 × 740 CSS px; allow vertical reflow with browser chrome, larger inputs/text, errors, and shorter viewports.
- One tap on Use location starts the existing lookup. About explains provider sharing and remembered automatic refresh; the location action retains an accessible description. Save only a boolean preference under `egg-cooker.auto-location.v1` in localStorage, never coordinates. About provides an off switch. Storage failure does not block a manual lookup.
- On a visible new visit, refresh once only when the preference is enabled, no cook is active and `navigator.permissions.query({name:'geolocation'})` reports `granted`. Prompt/denied/unsupported states wait for a user tap. Manual environment edits, Start and cancellation invalidate pending permission checks and location work. No polling or fresh requests on slider changes or focus. The browser controls permission duration; no promise of permanent access. Real active recovery never initiates location lookup.
- Refresh refinement accepted 2026-09-15: retain the displayed conditions, sliders and estimate while location/elevation/weather requests are pending; apply the final result together. Show progress only after 800 ms and suppress duplicate activation immediately without dimming the button. Only a completed failure or timeout applies the existing standard/altitude fallback with its explanation. Cancel lookup preserves the displayed conditions; Start freezes those displayed conditions and cancels pending work.
- Start/return egg motion lasts 1000 ms with a gentler easing; reduced motion remains immediate. No changes to clock accuracy while moving.
- Back immediately ends any cook and returns to preserved configuration. There is no cancellation confirmation. Removing a timer does not physically stop heating.
- At Ready, show Stop timer below demo speeds and above Cook another egg. Stop freezes the current time and egg frame, cancels scheduled sound/reminders/rendering and deletes the real active record. The result remains visible as “Egg taken out”; speeds and Stop disappear, Cook another egg and Back remain. A stopped result is not history and disappears on reload. Storage failures retain the existing explicit warning. Cook another egg can also return directly while overdue.

## Browser evidence and limits

Checked 2026-09-15: [Apple Safari site settings](https://support.apple.com/guide/safari/websites-ibrwe2159f50/mac) provides Ask/Deny/Allow for location. [Apple iPhone privacy settings](https://support.apple.com/guide/iphone/browse-the-web-privately-iphb01fc3c85/ios) describes per-website location settings. [Permissions query](https://developer.mozilla.org/en-US/docs/Web/API/Permissions/query) documents permission-state inspection. The app cannot set browser permission retention; unsupported queries fall back to the direct action.

Verify continuous timing bounds/anchors/versioned recovery; actual rail taps, drag and keyboard input; fresh defaults; one-tap and granted repeat lookup, opt-out and unsupported states; late-lookup isolation; stopped frame/time/audio/storage; direct Back; phone fit and continuous motion. Run both production-path gates and inspect rendered output. Safari permission persistence, actual-device touch/VoiceOver/audio, perceived joy and kitchen trials require human acceptance.

## Accepted polish — 2026-09-16

The maintainer requested centered preset anchors, visible boiling temperature, a city/locality label, stronger countdown/alarm cues and a fully reconciled living MVP. [0001](0001-mvp.md) now contains the consolidated contract, including all prior session feedback. S/M/L/XL now set 50/60/70/80 g over the same 40–90 range. Texture extends to 2.25 so the Soft/Jammy/Firm centers line up symmetrically; no firmer illustration or new physics model. Temperature controls stay unchanged.

Start shows time and water boiling temperature; below 85 °C an exploratory-texture note appears. The threshold is a product caution based on protein complexity, not an exact doneness cutoff. BigDataCloud supplies an optional independently fetched locality with the existing request bounds/cancellation guard; About holds its data-sharing/credits. No coordinate/name persistence. Final ten seconds tick; Ready repeats a three-tone alarm every two real seconds until acknowledged or muted. Existing hidden-page and recovery limits remain.

## Accepted fine-tuning — 2026-09-16

Texture highlighting covers the entire continuous range using the nearest anchor: Soft below 1.25, Jammy from 1.25 to below 1.75, Firm from 1.75 through 2.25. Midpoints select the higher category. The separate “Longer” output is removed; timing, anchor positions and illustration limits stay unchanged. Configuration, cooking summaries and accessible category names use these same three labels.

Add a **Location data** heading, separated from the texture rail by at least 16 px. When a city/locality is available, show **[City] · [pressure] hPa** on one line without “Local.” Long names truncate visually with the full name retained in text/title; pressure and Refresh remain visible. Without a name, retain the existing source feedback (including **Standard · 1013 hPa**). Source details stay available in About. Preserve one-screen default configuration at 390 × 740 and 390 × 844.
